# Выравнивание и одинаковый размер

Реализует #24 (historical issue #24), корпус A-EDITOR-079/080, поверх [множественного выбора](group-selection.md). Native-схема не меняется.

## Действия

Выберите минимум два экземпляра и сделайте один из них опорой. Нажмите **Выровнять…** над полотном либо **Правка → Выровнять и одинаковый размер…**. Окно показывает имя и полный ID опоры, количество экземпляров и соединений. Имя выводится как текст.

| Команда | Что меняется у остальных экземпляров |
| --- | --- |
| Левые края | X становится равен X опоры |
| Центры по X | Горизонтальные центры совпадают с учётом сетки |
| Правые края | Правый край совпадает с правым краем опоры |
| Верхние края | Y становится равен Y опоры |
| Центры по Y | Вертикальные центры совпадают с учётом сетки |
| Нижние края | Нижний край совпадает с нижним краем опоры |
| Одинаковая ширина | Ширина становится равна ширине опоры |
| Одинаковая высота | Высота становится равна высоте опоры |
| Одинаковый размер | Обе стороны становятся равны сторонам опоры |

Опора всегда остаётся без изменений. При изменении размера сохраняется верхний левый угол. Junctions участвуют как обычные occurrence bounds; их существующее круглое обозначение по-прежнему центрируется внутри этих границ.

В смешанном наборе команды применяются ко всем выбранным экземплярам. Соединения сохраняются в наборе, но не являются прямоугольниками выравнивания. Это явно поясняется в окне. Если опорой выбрано соединение, команда недоступна; щелчок по уже выбранному экземпляру делает его опорой, сохраняя набор.

## Сетка и маршруты

Вычисления выполняются в целых десятых долях единицы. Native-формат допускает координаты только на сетке 0.1. Если совпадение центров требует половины шага, координата округляется к ближайшей десятой; равное расстояние округляется в положительную сторону, как `Math.round`. Поэтому центры могут отличаться не более чем на 0.05. Положительные и отрицательные половинные значения проверены отдельно; отрицательный ноль не создаётся.

Используется общая политика перемещения рисунков. Если оба endpoint drawing видимого внутреннего соединения получают одинаковый вектор, его raw route points, anchors и заданная подпись следуют за ними. При разных векторах или неподвижном внешнем конце ручная геометрия остаётся абсолютной, а автоматическое отображение концов пересчитывается. Изменение ширины/высоты не перемещает ручные точки. Скрытые viewpoint маршруты не изменяются.

## Атомарность

До изменения проверяются все новые bounds и переносимые ручные точки. Если результат хотя бы одного участника выходит за диапазон ±1 000 000 либо нарушает положительность размера/сетку, отклоняется вся группа. Окно остаётся открытым с объяснением; частичного применения нет.

Одна кнопка создаёт одну команду и один Undo. Повторение уже достигнутого выравнивания или размера не создаёт команду, не меняет ревизию, dirty baseline или Redo. ID, имена, документация, свойства, профильные приложения, zIndex, `parentOccurrenceId` и другие виды сохраняются.

Окно привязано к store, ревизии, виду, набору и опоре. Отмена, смена вида/выбора/проекта и устаревшая кнопка не могут применить действие к другому контексту. Незавершённое inline-редактирование блокирует открытие до обработки pointer focus, сохраняя черновик. После успешного действия фокус возвращается к кнопке выравнивания.

## Проверка

- `schemka-model-ui/test/alignment.test.js`: все девять операций; неизменность опоры, остальных данных и видов; junctions; positive/negative center rounding; нулевой результат и обе ветки истории; ошибка одного участника; устаревшая ревизия; равные и разные векторы связанных рисунков; native roundtrip.
- `schemka-model-ui/test/alignment-app.test.js`: операции через фактические DOM-обработчики, явный mixed selection scope, literal anchor ID/имя, изменение размера и сохранение угла, отмена, no-op, stale action, фокус, ограничения группы и защита незавершённого черновика.

Реальная проверка Windows, DPI и работы клавиатуры с системными окнами остаётся финальной приёмкой после завершения очереди в `main`.
