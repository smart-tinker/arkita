## Как подтверждается завершение

[program.json](program.json) содержит все 339 исходных ID. У каждой применимой записи указан issue, текущее наблюдение и остаток. Девять исходных исключений сохраняют обоснование в карточках. Новые исключения из-за трудоёмкости не вводятся. Дублирующая A-EDITOR-126 ссылается на A-ADV-020.

Прежняя ограниченная инвентаризация сохранена у записей в `previous_inventory`:
её `absent`/`partial` не описывают новое дерево 0.6.0. Текущий
`current_status: acceptance-pending` означает незавершённую проверку исходных
критериев, а не отсутствие или полноту реализации. `implementation_ledger`
ведёт к актуальным маршрутам, тестам и ограничениям направления. Alias
A-EDITOR-126 остаётся ссылкой на A-ADV-020; девять исключений сохранены.
Принятые критерии записываются в `closed_criteria` только со ссылками на код,
проверки и слитый PR. Эта актуализация не добавляет закрытых критериев.
Исторические `coverage.json`, исходные карточки и источники не переписываются.

Каждый PR должен давать доступный пользователю результат, сохранять формат и историю либо содержать принятую миграцию, проходить затронутые проверки и независимое ревью. Для UI дополнительно проверяется реальный renderer; для сохранения — не только успешный путь, но и отказ, конкурирующая запись и восстановление. Ограниченный PR не закрывает всё направление, если остаются критерии исходных карточек.

Перед завершением #39 все применимые критерии должны иметь проверяемое состояние. Оставшиеся реальные Windows проверки получают конкретные сценарии и сохраняют `unrun` до исполнения на Windows. Отсутствующая реализация не переименовывается в Windows-проверку. После последнего слияния общий runner и проверка синтаксиса выполняются на точном `main`; исходники, дистрибутив и передаваемый SHA должны совпадать.

## Передача и готовность релиза

После завершения реализации локальная приёмка использует точный итоговый source, дистрибутив и сценарий Windows-проверок. Предварительные проверки unpacked bundle не являются приёмкой окончательного установщика. Он проверяет настоящие native dialogs, файловые ассоциации, несколько окон/экранов, clipboard, DPI, шрифты, печать и Git в поставке Windows. Релизный тег создаётся там по поручению владельца.

Исторический [persistence HOLD и нормативные ограничения](../RELEASE-1.0-READINESS.md) остаются проверяемыми записями. Исправление должно закрывать конкретный воспроизведённый риск с новым результатом проверки. Оно не стирает прежнюю приёмку и не заменяет нормативное подтверждение ArchiMate 4. Текущая package version не выбирает автоматически номер нового релиза.
