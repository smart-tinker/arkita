Дата: 2026-11-12

Исходники: `main` `62aa1639752be2d4d345c97f4610e3673f0e5767`
CI того же SHA: [run 43201799027](https://github.com/smart-tinker/arkita/actions/runs/43201799027) — Ubuntu и Windows jobs успешны.

Здесь зафиксировано наличие кода и уже имеющихся тестов, а не приёмка каждого критерия. Тесты в этой сверке не запускались повторно. Для визуальных и native-сценариев не использовались пользовательская Windows VM и опубликованный пакет; их статус — `UNRUN`. Успешный Windows runner CI не заменяет такую приёмку. `program.json` сохраняет всем критериям `acceptance-pending`, `windows_acceptance: unrun` и пустой `closed_criteria`. Исторический `coverage.json` не менялся.

## Решение и следующий шаг

- В актуальном `main` уже есть существенная реализация вложенности и оформления связей, поэтому старые `Факт по коду` из базовых карточек не следует читать как текущую инвентаризацию. Текущие evidence и остатки закреплены в `program.json`.
- Явные остатки source/test: диагностика пары вложенных рисунков (`A-ADV-028`), общая стратегия ортогонального примыкания (`A-ADV-127`), multi-view regression (`A-ADV-132`) и проверка route-relative label behavior (`A-EXT-014`). `A-ADV-126/128/129/130/131` имеют отдельные визуальные или export/print пробелы, не основание расширять код без подтверждённой потребности.
- Ветка `0.7.1-rc.1` остаётся только для согласованных Windows test/CI fixes. Новые editor features из этого аудита — отдельные задачи после RC, в `0.8.0-alpha.1`. Issue #16 остаётся открытым, пока нужные решения/регрессии и применимая Windows-приёмка не подтверждены.
- Ближайший минимальный порядок: (1) добавить только multi-view regression для уже существующего rebind, (2) решить, нужны ли пользователю три feature gaps и зафиксировать их контракты отдельно, (3) провести короткий native smoke на представительной модели для изменённых сценариев. Максимальные capacity/стресс-сценарии не являются обязательной частью этого issue.
