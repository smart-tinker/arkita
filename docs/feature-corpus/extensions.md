# Дополнения к корпусу Archi → Arkita

Срез источников: **18 октября 2026 года**. Базовая версия Archi — **5.10.0**; дополнительно просмотрены изменения 5.9 и 5.8, страницы официальной Wiki из реестра и четыре выбранных семейства плагинов. Реестр, ограничения доказательств и исключения: [sources.md](sources.md).

Это дополнение к корпусу User Guide, а не второй независимый backlog. Карточки с пометкой **«уточнение»** дополняют критерии соответствующей основной фичи; отдельный issue нужен только для обнаруженного пробела. **«Кандидат»** означает предложение для Arkita, а не утверждение, что аналог уже работает в Arkita или обязан войти в ближайший релиз. Поведение и критерии ниже — проектные требования для Arkita, сформулированные по мотивам источников; это не пересказ гарантий Archi.

## Правила чтения

- **G** — механика редактора, не зависящая от версии нотации.
- **A** — требуется применить правила и метамодель ArchiMate 4; поведение Archi 3.2 не является нормативным эталоном.
- **C** — совместимость форматов: необходимы явное преобразование и отчёт о неперенесённых данных.
- Сверка с исходным main вынесена в [coverage.json](coverage.json); фактическая пользовательская приёмка **не подтверждается одним статусом кода**. Наличие похожего кода или теста не закрывает критерии. Уже существующие Git, профили, история и операции с видами нужно расширять, сохраняя их контракты.
- Все изменения модели проходят существующие команды, валидацию и Undo/Redo. Чтение, поиск, предварительный просмотр и навигация не меняют модель и признак несохранённых изменений. При отмене или ошибке не остаётся половины операции.
- Для пользовательского интерфейса обязательны проверяемые клавиатурные действия, видимый фокус, понятная ошибка и сохранение введённого текста при исправимой ошибке. Linux UI-проверка и Windows acceptance фиксируются раздельно.
- Связи issue/PR и результаты тестов заполняются при реализации. Порядок новых фич не следует называть P0–P3: эти уровни предназначены для тяжести подтверждённых ошибок.

## Граница реализации

Карточки не предписывают Eclipse/RCP, JGit, Java, Jasper, OSGi, `.archiplugin`, синтаксис ACLI или файловую структуру coArchi. Готовый portable-дистрибутив Arkita и встроенный Git используются как существующая база. Импорт coArchi/GRAFICO не следует автоматически из A-EXT-035–039: он потребовал бы отдельного адаптера модели, явной миграции 3.2 → 4 и проверки потерь.

Первые полезные применения этого дополнения — усилить критерии **поиска/where-used, group selection, Undo/cancel, документации и экспорта**. Автоматизации, собственный движок запросов, галерея, XLSX и расширенный Git UX имеют отдельную оценку ценности и зависимостей. Наличие записи в полном корпусе не означает обещание реализации в одной итерации.
