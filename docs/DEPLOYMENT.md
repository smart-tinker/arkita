# Перенос без Sites

## Сборка

На Node.js 22+: `npm ci --ignore-scripts`, `npm test`, `npm run check`. Результат в `dist/`; зависимости npm нужны для тестов, runtime использует только локальные файлы. Не публикуйте корень репозитория, `.env`, реальные JSON, журналы или `node_modules`.

Локальная проверка: `npm start`; сервер слушает только `127.0.0.1`, не предназначен как production-сервер. Генератор пересоздаёт собственный `dist/` с нуля и отклоняет symlink вместо этого каталога. Для релиза используйте проверенный checkout.

## Обычный статический хостинг

Загрузите только `dist/` в document root nginx, Apache, Caddy или аналогичного сервера. Нужны directory indexes, корректный JavaScript MIME и HTTPS. Настройте редиректы `/mermaid` → `/mermaid/`, `/model` → `/model/`, `/catalog` → `/catalog/` с сохранением query. Не переписывайте отсутствующие `.js` файлы на HTML. Приложение рассчитано на корень origin, не на `/some/subpath`.

Пример блока nginx для будущего отдельного хоста (не применён автоматически):

```nginx
server {
  listen 8080;
  root /srv/schemka/dist;
  index index.html;
  include mime.types;
  add_header X-Content-Type-Options nosniff always;
  location / { try_files $uri $uri/ =404; }
}
```

TLS, реальный домен, доступы, серверный auth, приватная сеть и deploy требуют отдельной настройки. Конфигурация выше не защищает приватные данные. CSP задан по страницам: у standalone Mermaid inline vendor-код требует `script-src 'unsafe-inline'`; нельзя без проверки навесить единую CSP, которая сломает редактор. Каталог рендерит импорт как текст, не HTML.

## Будущие подключения

`platform/contracts.ts` описывает `AuthProvider`, `RepositoryProvider` и явные `ModelBinding`. Это декларации границ, не реализация. Не хранить GitHub PAT/API keys в браузере, исходниках, localStorage или URL. Серверный адаптер должен проверять пользователя и права, ограничивать репозиторий/пути, защищать от CSRF и сравнивать ожидаемую revision перед записью. OAuth, доступы и секреты сейчас не создавались.

Публичная документация/ландшафт должны оставаться отдельными от приватных реальных моделей. Реальный home JSON можно открыть в каталоге локально: он не входит в сборку и не уходит в сеть. Для автоматического связывания моделей сначала согласовать стабильные ID и правила разрешения конфликтов; совпадение названий недостаточно.

## Что этот этап не обещает

Нет backend, входа, реального GitHub sync, автосохранения, совместного редактирования, полной ArchiMate 4 нотации/валидации или автоматического преобразования Mermaid в модель. Браузерная визуальная QA отражается отдельно в VALIDATION.md. Не считать synthetic fixture описанием работающей инфраструктуры или гарантией актуального health.
