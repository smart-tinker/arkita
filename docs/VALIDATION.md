## Targeted UX implementation guidance

Palette search uses a visible label, stable native controls, literal bounded matching and a separate result summary. Result counts are a polite status region rather than making the whole palette live; filtering does not move focus to results. Clear returns focus to the field, and Escape clearing respects IME composition. Each query refresh captures one model snapshot, replacing the previous 58-copy pattern; a regression pins this bound. These choices use W3C's primary explanatory guidance for [labels](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html), [status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) and [visible focus](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible). They are targeted design criteria, not a full accessibility-conformance assessment.

Fit is an overview operation. For example, a 750×610 view fitted into 770×430 yields a scale near 0.705: an 11-unit relationship label becomes about 7.75 CSS pixels. The fixed non-Fit 900×640 view is not a true 100% zoom and may not improve readability. Readable zoom/viewport control is a separate unresolved UX task; this palette change does not alter route geometry, font scaling or collision rules.
