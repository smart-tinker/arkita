# Автоматизация, CLI и подключённые ресурсы

Arkita запускает локальные декларативные пакеты JSON вручную. Пакет не является
JavaScript, не получает Node, файловую систему, сеть или доступ к паролям.
Открытие модели, импорт файла и выбор объекта не запускают автоматизацию.
Пакеты хранятся в локальных настройках приложения, отдельно от `.arkita` и Git модели.

## Локальные пакеты

Откройте «Автоматизация и расширения…». Встроенный пример запрашивает элементы без
рисунков. Его можно проверить, сохранить как `.arkita-automation.json`, установить,
затем отдельно разрешить ручной запуск. После установки или обновления пакет отключён.
Перед установкой видны ID, версия, описание, engine и запрашиваемые возможности.
Удаление/отключение действует сразу; перезапуск не нужен, данные моделей сохраняются.
Неудачная проверка или запись локальной библиотеки сохраняет предыдущую библиотеку.

Минимальный пакет:

```json
{
  "format": "arkita-automation",
  "version": 1,
  "id": "team.unused-elements",
  "name": "Элементы без рисунков",
  "packageVersion": "1.0.0",
  "description": "Только чтение текущей модели.",
  "engineVersion": 1,
  "capabilities": ["model.read"],
  "steps": [{ "action": "query", "query": { "kind": "element", "unused": true } }]
}
```

`model.read` обязательно. Для изменения требуется также `model.write` и подтверждение
точного предпросмотра каждого запуска. Другие capabilities отклоняются. Выберите
пакет, разрешите запуск и нажмите «Подготовить запуск». Журнал показывает входную
модель, ревизию, результаты запросов, старые/новые метаданные и аргументы команд.
Только «Применить изменения» меняет модель одним Undo. Сохранение файла/коммит Git
остаётся отдельным действием. Отмена, ошибка, отключение пакета и устаревшая модель
не оставляют часть пакета. No-op не добавляет Undo. Журнал не перехватывает фокус.

Версия контракта 1: не больше 64 KiB на пакет, 32 установленных пакетов, 100 шагов,
200 команд, 8192 записей одного запроса, 8 MiB результатов/предпросмотра и 5 секунд
подготовки. Между шагами управление возвращается UI; отмена и deadline проверяются
между командами. Это закрытая последовательность валидируемых операций, без циклов,
`eval`, пользовательских функций или произвольных исполняемых модулей.
Ошибка содержит код и шаг; для JSON и шага указывается строка. Для выполнения номер
строки относится к каноническому JSON пакета с отступом в два пробела.

### Запросы и команды

Чистый API `schemka-model-core/src/automation.js`:

- `queryModel(snapshot, query)` возвращает отдельные записи с `kind`, стабильным `id`,
  `viewId` для рисунков, `name`, `type`, `drawingCount`, ordered `properties`, `record`.
  Фильтры: `kind`, `ids`, `type`, точные `propertyKey`/`propertyValue`, `unused`.
  Области: project, element, junction, relationship, view, folder, occurrence,
  connection, visualNode, visualConnector. `unused` означает отсутствие рисунков
  концепта во всех представлениях, как счётчик использования в UI.
- `prepareAutomation(snapshot, manifest, {signal})` готовит проверенный снимок и
  отчёт отдельно от открытой модели. `action:query` читает; `rename` добавляет
  `prefix`/`suffix`; `setProperty` задаёт `key`/`value` через штатный bulk metadata.
- `action:command` принимает закрытые штатные команды renameProject/View/Element/
  Relationship/Junction, createView, createElementAndOccurrence,
  createJunctionAndOccurrence, createRelationshipAndConnection. Аргументы и ссылки
  проходят обычную core-валидацию. Для создания нескольких объектов укажите
  стабильный ID существующего представления в каждой команде; автоматических
  ссылок на результат предыдущей команды в v1 нет.

Метаданные концепта редактируются по его ID, occurrence/connection не подменяют
концепт. Перед подтверждением renderer ещё раз проверяет store, document token,
ревизию и неизменность разрешённого пакета. Команда `applyProjectSnapshot` остаётся
внутренним атомарным механизмом UI и не разрешена как команда пакета.

## CLI из установленного приложения

Внешний Node не нужен: `Arkita.exe --cli` обрабатывается до загрузки GUI и до
single-instance lock. Существующее окно остаётся открытым. На Windows используйте
ожидание завершения и явное перенаправление stdout, поскольку Arkita — GUI executable.
Пример PowerShell (выходной каталог CSV должен отсутствовать):

```powershell
$arkita = "$env:LOCALAPPDATA\Programs\Arkita\Arkita.exe"
$job = Start-Process -FilePath $arkita -Wait -PassThru `
  -ArgumentList '--cli validate --input "C:\Модели\Архитектура.arkita"' `
  -RedirectStandardOutput "$env:TEMP\arkita-validation.json" `
  -RedirectStandardError "$env:TEMP\arkita-validation.stderr"
$job.ExitCode
Get-Content "$env:TEMP\arkita-validation.json" -Encoding UTF8

$job = Start-Process -FilePath $arkita -Wait -PassThru `
  -ArgumentList '--cli export-csv --input "C:\Модели\Архитектура.arkita" --output "C:\Модели\CSV-новый"' `
  -RedirectStandardOutput "$env:TEMP\arkita-export.json"
$job.ExitCode
```

Путь executable зависит от выбранного каталога установки; для portable укажите его
фактический путь. Для разработки тот же контракт доступен через
`node scripts/arkita-cli.mjs validate --input …`.

Stdout содержит одну JSON-запись с `status`, `code`, `exitCode`, `command`, данными
модели и `warnings`/`files`; ошибка содержит `message`. Exit codes: `0` — успех,
`2` — завершено с предупреждениями, `1` — ошибка. Чтение старого формата выдаёт
предупреждение и не переписывает исходник. CSV предупреждает о непереносимых
представлениях/рисунках; нативная модель сохраняется целиком только `.arkita`.

Порядок: аргументы → bounded чтение и валидация → подготовка экспорта → создание
нового каталога → exclusive запись → readback. Существующий каталог или файл не
перезаписывается. Ошибка записи сообщает `incompleteOutput`; частичные файлы
оставляются для осмотра, успех не объявляется. Кириллические входные/выходные пути
проверяются temp integration test. Пароли и сетевые операции в CLI отсутствуют.

## Host policy

В диалоге Git откройте «Подключения и внешние ресурсы…». До первого подключения
сначала заполните адрес, ветку и каталог в окне Git. Настройка принадлежит этому
точному сочетанию и хранится рядом с его private bare repository; global Git config
не меняется. На каждом fetch/ls-remote/push политика читается заново, включая
публикацию вех; отключение действует и в другом окне с тем же подключением.

- Системный режим использует текущую конфигурацию Git/окружения.
- Direct и manual применяются только к HTTPS: удаляют у дочернего процесса proxy
  env и задают явный общий и URL-specific `http.proxy`. Manual принимает только
  HTTP/HTTPS сервер и порт без логина, пароля, пути и query.
- SSH использует свою системную конфигурацию. Arkita не переписывает SSH config.
- «Разрешить подключение» выключает сетевые команды Arkita, сохраняя локальные
  версии, историю и модель. Это не удаление общей записи Credential Manager.
- Диспетчер учётных данных запускается фиксированной native-командой Windows.
  Пользователь сам выбирает запись для удаления. Arkita не читает и не возвращает
  секреты. Общая запись может использоваться другими репозиториями и программами.

Локальная справка и текст модели доступны offline. Активные HTML/JavaScript-подсказки
не поддерживаются. HTTP/HTTPS ссылка открывается только отдельной явной командой,
после native подтверждения, в системном браузере. Локальная `file://` ссылка
проверяется в main process и открывается через назначенный в Windows обработчик
только после отдельного native подтверждения; UNC и другие удалённые пути,
параметры ссылки и несуществующие файлы отклоняются. Другие schemes, userinfo,
встроенные privileged browser/webview и автоматическое открытие запрещены.
Недоступный сайт или файл не выполняется внутри инспектора и не блокирует модель.

## Доказательства и пределы

Focused core/DOM/native tests проверяют атомарность/Undo, отмену/stale, capability и
version rejection, quota preservation, bounded output, Unicode CLI/no-overwrite,
preload/sender/token guards, реальный local bare Git и эффективный Git proxy config.
Source app DOM проверяет вход в host policy из рабочего Git-диалога.
Это не Windows GUI/установщик/network acceptance. Реальные Windows direct/proxy/auth
failure, браузер по умолчанию, Credential Manager и CLI stdout/exit из установленного
executable проверяются отдельно в протоколе проверки целевого Windows-релиза. Активные подсказки и
исполняемые JS/Java плагины в этой версии отсутствуют намеренно.
