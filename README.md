# Arkita

**Arkita — самостоятельное настольное приложение для моделирования архитектуры
в нотации ArchiMate 4, для Windows x64.** Функциональный ориентир — Archi:
дерево модели, представления, полотно, палитра, свойства и отношения.
«Схемка» — отдельный редактор Mermaid.

## Версия и распространение

Текущий исходный снимок соответствует Arkita 0.7.1-rc.1. Исторические бинарные
пакеты и отчёты приёмки в этот публичный репозиторий не перенесены; здесь пока
нет опубликованных установщиков. Проверенные будущие сборки будут размещаться
на [странице выпусков](https://github.com/smart-tinker/arkita/releases).
Для сборки, Windows-пакетирования и проверки см. [руководство Windows](docs/WINDOWS.md)
и [правила разработки](CONTRIBUTING.md).

Исходный код Arkita распространяется по лицензии MIT; полный текст находится
в `LICENSE`. `LICENSES.md` и `THIRD-PARTY-NOTICES.txt` описывают лицензии и
уведомления сторонних компонентов.

## Первый сценарий

1. Создайте модель или откройте учебный пример через меню «Файл». Для переноса
   Archi выберите поддерживаемый native XML 5.0.0, изучите полный отчёт и решения
   о преобразованиях до применения; сохраните результат в отдельный `.arkita`.
2. Добавьте объекты из палитры. Протяните отношение между рисунками;
   «Магическая палочка» предложит тип после перетаскивания.
3. Откройте модальные «Свойства»: имя, документация и пользовательские поля
   относятся к общему объекту, оформление и геометрия — к его рисунку.
4. Создайте ещё одно представление с теми же концептами. Вкладку можно закрыть
   без удаления представления; другую модель можно открыть в отдельном окне.
5. Сохраните `.arkita`. Ctrl+S обновляет привязанный файл, Ctrl+Shift+S сохраняет
   под новым именем. Передайте копию коллеге или подключите модель к Git.

## Возможности исходников

- [Единое дерево модели](docs/MODEL-TREE.md): фиксированные разделы и пользовательские
  папки внутри, поиск по всей модели, переход к использованиям,
  Navigator, Visualiser, анализ и генерация представлений. Расширенный поиск,
  замена и массовые свойства имеют предпросмотр и одну операцию Undo.
- Множественное выделение на полотне и в дереве, выравнивание, групповые операции,
  вложенность, маршруты, независимое оформление, заметки, группы, легенды,
  изображения и ссылки на виды. Геометрическая вложенность сама по себе
  не создаёт смыслового отношения.
- Раздельные окна моделей, вкладки видов, недавние файлы, отделяемая палитра,
  настройки панелей и клавиатуры. Локальные настройки сохраняются отдельно
  от модели. Резервные копии **перед сохранением** включены по умолчанию для новых
  настроек; ранее сохранённый выбор сохраняется. Поиск и восстановление
  доступны в меню «Файл»; восстановление создаёт только новый файл. Периодического автосохранения нет.
- Перенос фрагментов между моделями, системный clipboard, явно выбранные reuse
  и независимое копирование. Между окнами Undo независим; при изменившемся
  источнике Cut сохраняет исходник и сообщает о копировании.
- SVG и PNG, PDF и печать, самостоятельные HTML-отчёты с исключением данных.
  Шаблоны моделей, Canvas/эскизы, специализации и viewpoints.
- CSV импорт/экспорт и XLSX экспорт, объединение моделей, Exchange XML через
  закреплённую XSD 3.1 Preliminary и ограниченный импорт Archi native XML 5.0.0.
  Анализ Archi собирает ошибки, преобразования и потери по объектам и видам;
  Gap → Assessment требует отдельного решения. Отчёт и таблица ID сохраняются,
  исходные типы/домены доступны после повторного открытия `.arkita`.
  Контрольный объём — 5016 native-записей при пределе 8192 и 8 MiB данных.
  Archi ZIP с ресурсами
  не поддерживается; полная совместимость ArchiMate 3.2 → 4 не заявляется.
- [Git](docs/GIT.md): локальные версии, typed сравнение, история, чтение ревизии,
  явное восстановление, локальные ветки, конфликты base/local/remote и вехи.
  Save, Commit, Push и Receive — отдельные действия; локальный commit
  не означает публикацию. Удаление вехи в UI локальное, опубликованный тег остаётся.
- [Декларативная автоматизация и CLI](docs/AUTOMATION-AND-HOST.md): запросы,
  проверенные пакеты команд с предпросмотром и одним Undo, управление локальными
  расширениями. Исполняемые JS/Java плагины и скрипты из модели не запускаются.

Это карта доступных маршрутов исходников. Формальное закрытие всех исходных
критериев, общий прогон финального SHA и проверка установленного приложения
отмечаются отдельно в [программе](docs/feature-corpus/PROGRAM.md).

## Файл модели и совместимость

`.arkita` — детерминированный UTF-8 JSON-контейнер `schemka-project-file@1`:
внутри список native JSON-записей по стабильным путям/ID, включая графические
ресурсы. Текущий writer использует **`schemka-project@4`**, метамодель остаётся
`schemka-archimate4@2`. Это не ZIP, база данных или исполняемый документ.
Файл можно хранить в Git, но для сравнения и совместной работы встроенный Git
использует отдельные JSON-записи вместо большого контейнера.

V2/V3 сначала проверяются по своей замороженной схеме, затем преобразуются
в памяти в V4. Сохранение требует отдельного **Save As** и сохраняет исходные
байты. Обратной конвертации нет; старый внутренний V1 отклоняется. Расширение
`.schemka.json` распознаётся для совместимости. [Контракт Native V4](docs/NATIVE-V4.md),
[исторические V2](docs/NATIVE-V2.md) и [V3](docs/NATIVE-V3.md).

Внешние изменения файла останавливают обычное сохранение. Дисковые журналы
сохраняют предыдущие, новые и фактически вытеснённые байты для явного
восстановления; это не блокировка других программ и не гарантия при потере
питания. Для записи требуется поддерживаемая файловая система с hardlinks.
Не записывайте одну модель одновременно из разных программ.
Успешное сохранение убирает только свой служебный журнал с доказанными
дубликатами. Новая версия должна совпадать с сохранённой моделью, прежняя при
перезаписи — с проверенной резервной копией. Для native-каталога дополнительно
проверяется точное совпадение прежних JSON-записей с каноническим экспортом
резервной копии; необычное форматирование сохраняется в журнале. Старые,
прерванные и неоднозначные журналы не очищаются. При отключённых резервных
копиях журналы перезаписи остаются. Это не очистка пользовательских копий.
[Границы native persistence](electron/README.md).

Представление — конкретная диаграмма. Viewpoint описывает аудиторию, задачи
и показываемые типы. Профиль задаёт повторяемые поля/специализации; для обычной
модели он необязателен. [Настройки](docs/LOCAL-PREFERENCES.md),
[профили и viewpoints](docs/PROFILES-AND-VIEWPOINTS-UI.md),
[командный профиль](docs/TEAM-PROFILE.md).

Подтверждённо запрещённые новые отношения отклоняются. `UNKNOWN` означает
недостаточность подтверждения правила, а не разрешение. Полное нормативное
соответствие ArchiMate 4 и сертификация не заявляются.
[Покрытие нотации](docs/ARCHIMATE-COVERAGE.md), [источники](docs/NOTATION-SOURCES.md),
[лицензии](LICENSES.md).

## Разработка

Автоматические проверки запускаются в GitHub Actions на Linux и Windows.
Реальный GUI, чистая установка и native dialogs проверяются отдельно на
целевом Windows-дистрибутиве.
Нужны Node.js 22.12+ и npm; версии зависимостей закреплены в lockfile.

```sh
npm ci --ignore-scripts
npm test
npm run check
node node_modules/electron/install.js
npm run desktop
```

`npm test` собирает `dist/` и запускает общий runner; `npm run test:desktop`
проверяет main/preload и дисковый I/O, но не заменяет Windows GUI.
`npm run package:win` создаёт NSIS-установщик без публикации. Для Linux-рецепта
с Wine см. [Windows guide](docs/WINDOWS.md). `npm start` обслуживает
вспомогательную web-сборку на localhost:4173 только для разработки интерфейса.

## Структура исходников

- `electron/` — desktop, системные диалоги, процессы и безопасный файловый доступ.
- `schemka-model-core/` — модель, команды, валидация и история.
- `schemka-model-profiles/` — каталог типов и диагностика.
- `schemka-model-io/` — native файлы, преобразования и экспорт.
- `schemka-model-ui/` — интерфейс редактора.

Унаследованные Mermaid `src/`, `vendor/`, старый `schemka-site-shell/` и
`schemka-catalog/` остаются в checkout, но не входят в установщик Arkita.
Частные модели и данные не входят в исходники и сборку;
[границы данных](docs/DATA-BOUNDARIES.md). Исторические результаты проверок
остаются в [VALIDATION.md](docs/VALIDATION.md) и не заменяют новую приёмку.
